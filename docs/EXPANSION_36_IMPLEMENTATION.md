## Dependency order

1. Shared project identity, immutable specifications, templates and evaluation/evidence foundations.
2. Productivity pages; ingestion/provenance and integrations; scoped delivery/review.
3. Typed mission graphs, experiment contracts, competency-based routing and memory lifecycle.
4. Durable replay, evaluated skills and controlled evolution.
5. App Factory vertical slices, repository import, visual/data tooling and browser QA.
6. Business Factory and Release Command adapters, supported real service acceptance.

## Completion rules

A catalog entry or page is not feature completion. Acceptance needs working controls, owner isolation, bounded resources, persistence, negative tests and deployed integration evidence. Starter tools must disclose supported formats/actions and outstanding functions. No unrelated auth, billing, external-write or operational gate is bypassed. Preserve existing evidence rather than repeat paid work.
