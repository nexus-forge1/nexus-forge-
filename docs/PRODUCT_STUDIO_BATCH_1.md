# Product Studio — first expansion batch

This batch implements bounded starter functionality for the six productivity additions plus Product Specifications and Unit Economics. It does not complete the full 36-feature request. All 36 items remain tracked in src/lib/expansion-catalog.ts and /expansion. The original 16-page guide, 18-page core tour and retired Multimodal Studio remain intact.

## Working scope

| Feature page | Implemented | Still required for the full request |
|---|---|---|
| /templates | Private reusable briefs, audience, criteria, budgets; atomic project plus unapproved mission; exact retry reuse | Reusable published/team template versions and more packs |
| /specifications | Explicit structured requirements compiled into immutable versions with roles, routes, entities and acceptance; linked draft mission receives requirements; approved/running contracts are frozen; exportable planned implementation trace | Natural-language/voice/document compilation, API/job/migration contracts and verified implementation links |
| /knowledge | Private immutable UTF-8 TXT/MD/CSV sources, SHA-256, bounded source-line passages and citation export | PDF/DOCX extraction, semantic retrieval and reviewed Council context attachment |
| /economics | Retained operator forecasts including failed-attempt cost, fees, margins, per-success contribution and break-even | Measured hosting/provider/storage imports and full accounting reconciliation |
| /connections | Actual registered public JSON adapters, explicit request keys, live lookup controls and enable/revoke; existing governed GitHub write plans remain reachable | OAuth account connections, service-specific scopes, authenticated connectors and richer health history |
| /changes | Exact requirement version comparison; positional saved-artifact line comparison; existing governed artifact revision creation | Repository/migration impact and reviewer approval workflow |
| /client-delivery | One verified existing recipient account, approved immutable artifact snapshot, digest, expiry, owner revoke and immutable recipient acceptance/revision decisions | Invitation delivery and genuine two-account deployed nonempty-artifact browser acceptance |
| /notifications | Actual studio events, owner-only read state and contextual links; client received/review notices | Broader mission/job/budget events and opt-in email/push |

No provider inference, checkout, outgoing invitation, delivery dispatch or production mutation is triggered by a template/specification/economics save. Client grant is an explicit data-sharing action; it requires a ready artifact and unique verified account. It does not grant mission execution or change artifact approval. Preview content remains escaped text; no artifact scripts execute. Revocation/expiry deny future server access but cannot retract content a recipient already read.

## Bounds and persistence

20 projects/operator; 100 private templates; 20 immutable specs/project with optimistic revision checking; 30 text sources/project (64 KiB each); 20 exact passages/source (100 lines and 8 KiB max); 30 economics scenarios/project; 50 client grants/operator; 30 immutable feedback records/grant; 500 studio notification history entries/operator with latest 100 displayed. Exact duplicate saves are reusable at the relevant limit. There are no automatic deletion or paid retry loops. Sources remain untrusted evidence and are not automatically promoted to memory or permissions.
